Case Study · 02

Three parties.
One access model.

Druva's partner console could only provision a limited product set, so MSPs lost deals. I designed provisioning and access across partner, customer, and Druva — within hard licensing limits, without exposing customer data.

Role
UX Designer
Domain
Backup & Cybersecurity
Focus
Provisioning & Access
Timeline
4+ months · Shipped
Context

Druva

Cloud-native backup and data security for endpoints, SaaS, data centers, and cloud workloads.

My scope

MSP partner console — provisioning, access boundaries, and onboarding flows.

MSP

An IT partner managing backup and data protection for many clients from one dashboard.

Problem

MSPs lost customers when MSC couldn't provision products outside its supported set. Licensing blocked the obvious fix — just add products.

How might we expand what MSPs can sell within licensing constraints — without breaking customer privacy?
Trust triangle
MSC Partner

Operations admin managing many customers from one console.

"I want more product modules so I can offer more services."

Customer

End admin whose environment the MSP manages.

"Keep my data private — no full MSP visibility into my console."

Druva Support

Internal team for licensing-restricted provisioning.

Scale Druva-led provisioning without manual bottlenecks.

System map

Mapped actors, customer types, access models, and state conversions — including irreversible ones — before drawing screens.

Flows

Each actor's work as page → action → result, so collisions surfaced before high-fidelity screens.

Four states

MSC- or Druva-provisioned × Restricted or Unrestricted. Partners read state at a glance; invalid conversions blocked before the click.

Restricted Unrestricted
MSC-Provisioned Core products only. No advanced workloads. Full MSP access to console, accounts, and reports for supported offerings.
Druva-Provisioned Licenses provisioned; no console access afterward. Full access plus workloads unavailable to MSC-provisioned customers.
Scenarios

Every path split across three portals — MSC, S-portal, C-portal — so no responsibility fell through a gap.

  • MSC — Create customers, convert provisioning type, switch access level, request temporary access
  • S-portal — Verify licenses on new products and edit requests
  • C-portal — Accept or reject MSP console access requests
What shipped

The provisioning and access model inside MSC — how partners onboard customers and manage access daily.

Some screens withheld or simplified under NDA.

Outcome

Self-serve expansion

Partners request and provision advanced workloads without a support ticket for every addition.

Clearer customer management

Four states legible at a glance. Invalid conversions blocked — partners see what's allowed and where the privacy boundary sits.

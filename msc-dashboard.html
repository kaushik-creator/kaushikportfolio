Case Study · 01

MSC — the operations dashboard for MSP partners

MSPs manage backups for hundreds of customers from one console. I designed the home screen that shows what needs attention — failures, storage, licenses, security — across every client at once.

Research question — what does an admin need to see first, and what can wait?

Role
UX Designer
Domain
Data Backup & Security
Focus
Dashboards, Monitoring
Type
Enterprise · B2B

Only designer on the project

Context

MSP — a partner company that manages backup and IT operations for many end-customers from one login.

MSC — Druva's Managed Services Center, the portal MSPs use to monitor every customer they support.

Method

I grounded this in three inputs, not assumptions: sitting in on live MSP admin calls, going through internal docs and Support Slack threads, and working sessions with PMs and engineering. That's where "what admins get stuck on" came from.

Alex — IT Operations Admin

Manages backups and security for every client the MSP supports — all from one login. Needs a single view of 100+ companies, highlighting only errors and expiring contracts.

If Alex misses a failed backup hidden inside a separate account window, the client loses data and the MSP risks losing the contract.

Built from the admin calls and Support threads — not a template.

The hardest constraint — role-based access

Different users need different data on the same screen architecture — without the layout looking broken or empty.

ComponentFull AdminLimited Admin
DashboardEvery customerAssigned customers only
Failure TriageFix any customerAssigned customers only
Security WidgetSee and dismiss risksHidden entirely
License ViewAll customersOwn customers only

Scoped out of this phase: the Limited-Admin view was specced, not visually designed this round. The architecture supports it.

Synthesis — information map

Mapping every metric turned the research into structure.

The 4 daily workflows
  • Immediate Triage: "Which customer backups require attention this morning?"
  • Daily Monitoring: "Is anyone using an abnormal amount of storage today?"
  • Weekly Planning: "Which client trials or contracts expire this week?"
  • Periodic Auditing: "Are our own admin accounts safe and secure?"
Decision — structure first

I tested structure with empty blocks so data and colour couldn't bias the hierarchy.

I checked these against the four workflows — every layout forced unrelated jobs into the same visual hierarchy.

Iteration & failure — scrapped directions

I moved into high fidelity to see how real data felt — these two directions failed stakeholder and workflow review.

Scrapped 01 — The Overloaded View

First pass put usage, licensing, lifecycle and tickets on one screen.

How I knew it failed: in stakeholder and engineering reviews, and against the four workflows, the licensing widgets kept getting skipped — storage charts dominated.

Scrapped 02 — The Half-Measure

Grouping accounts/workloads/security at the top fixed the top half.

How I knew: walking it through with PMs — account management and consumption analysis are two different mental modes; usage charts felt orphaned at the bottom.

Decision — five categories

I stripped it to five labelled categories to see the structure with no UI noise.

These five categories did not belong on one scroll — that led directly to three tabs.

Tab 01

Accounts & Licensing

Commercial attention and support cases.

Tab 02

Usage Monitoring

Consumption and quota alerts.

Tab 03

Backup Triage

Morning failure triage.

Tab 01 — Accounts & Licensing

Which customers need commercial attention today?

Tab 02 — Usage Monitoring

Which tenants are consuming resources abnormally?

Known tradeoff: per-product numbers live in the hover tooltip, not separate cards — scannable for one line that moved, wrong for side-by-side comparison.

Tab 03 — Backup Triage

Which customer backups require attention this morning?

Triage was structurally simple — it went straight to final.

Outcomes
01 · Sequence the work

Mapping information architecture first made every later UI decision easier — each screen already had a validated purpose.

02 · Separate quick from slow

Daily tasks (renew a contract) and analytical tasks (read a 90-day trend) need different mental states. Tabs reduced context switching.

03 · Tabs hide context

Three tabs fixed crowding but scatter alerts — a broken backup, expiring plan, and quota warning now live on three surfaces.

04 · Validation

Defined, not yet measured — pre-launch, no before/after yet. Every tab maps to a workflow admins described; scrapped directions were cut for reasons I can point to. Post-launch I'd track time-to-triage and missed license expirations.

Under NDA — interface redrawn for presentation; logic and constraints true to production.
